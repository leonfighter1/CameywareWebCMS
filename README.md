# Cameyware 网站内容管理（CMS）

公司官网（www.cameyware.com，仓库 `C:\Cameyware`）的内容管理系统：页面、区块、全局资料和界面文字都存在这里自己的数据库里，
用四种语言（简体、繁體、English、Français）编辑，签入后推到预览站，检查过再推到正式站，不用再改代码、推代码。

## 网址

| 网址                                                           | 本机                  | 是什么                                               |
| -------------------------------------------------------------- | --------------------- | ---------------------------------------------------- |
| [cms-edit.cameyware.com](https://cms-edit.cameyware.com)       | http://127.0.0.1:8790 | CMS 中心页和各个编辑页                               |
| [cms-preview.cameyware.com](https://cms-preview.cameyware.com) | http://127.0.0.1:8791 | 带 Edit 的官网：每个区块上都有 Edit，点了去改它      |
| preview.cameyware.com                                          | http://127.0.0.1:8787 | 预览站（禄命秘解的服务器），“推到预览站”后是新的一版 |
| www.cameyware.com                                              | —                     | 正式站（Cloudflare Pages），“推到正式站”后几分钟上线 |

两个 CMS 网址要在 Cloudflare 隧道里各加一条公共主机名，并放进保护预览站的 Access 应用（见 docs/tech-plan.md）。

## 怎么用

1. **登录**：在官网登录员工账号，打开“我的账号” → “网站内容管理” → “进入 CMS”。网站编辑、管理员和超级管理员能进；只有管理员和
   超级管理员能推到正式站。右上角可以切换中文和 English。
2. **拿取**：每个页面、区块、全局资料和每条界面文字都是一个文件。在它的编辑页上点“拿取”，它就在你名下，只有你能改；别人名下的可以“接手”；
   已签入工作流的锁定着，谁都拿不了。
3. **改内容**：在 cms-preview 上点区块的 Edit，或在中心页打开页面、区块、全局资料、界面文字。保存的是草稿：CMS 预览切到“草稿”就能看到。
4. **签入**：在“我的文件”勾选要签入的文件（可以几个一起），写一句说明。签入后文件锁定在工作流的“已签入”，CMS 预览（“已签入”）马上能看到。
   不改了可以“放回”（修改留着，谁都能拿取）或“丢弃”（回到正式站的版本）。
5. **推到预览站**：在“工作流”页勾选已签入的文件，点“推到预览站”：正式站加上预览站上已有的和这些文件，构建好换到 preview.cameyware.com（一两分钟）。
   在“已签入”这一步也可以“终止工作流”：文件回到签入的人名下，修改留着。
6. **推到正式站**：在“预览站”这一列勾选检查过的文件，点“推到正式站”：正式站只加上这些文件，以 GitHub 上的官网为底提交 content/site.json 并推送，
   Cloudflare 几分钟后上线；文件回到没人拿取的状态。预览站上的文件也可以“退回签入”：预览站重新构建，不再有它们。
7. **版本**：每个文件的编辑页都有“版本”，列出每次签入，标出正式站的版本；拿取后可以把任何一个版本恢复为草稿，再照常签入。紧急情况下，
   管理员可以在“工作流”页让正式站整体回到以前上过正式站的一版。
8. **下载与上传**：整个网站、界面文字、单个页面、区块或全局资料都能下载成 JSON 或 XML，改好再上传；先列出会改什么，确认后写成草稿。要改的文件
   要在你名下或没人拿取（会自动拿取）。上传一个地址还没有的页面，就新建一个页面。

## 区块类型

横幅、作品横幅、页面标题、账号卡片、精选作品、作品列表、卡片网格、服务卡片、折叠问答、提示条、公司联系方式、图文、自由 HTML、图片、
按钮组。每种类型在官网里有自己的显示方式（`C:\Cameyware\src\cms\views.tsx`），字段写在官网的 `cms/types.json`。自由 HTML 可以放脚本，
在隔离框里运行，碰不到网站的登录信息。

## 命令

```
npm start          # 启动 CMS（8790）和 CMS 预览（8791）；第一次会构建 CMS 和 CMS 预览站
npm run build:site # CMS 没运行时重建 CMS 预览站（运行时用中心页的“重建 CMS 预览站”）
npm run sync       # 从官网和禄命秘解同步内容模型、区块目录和网址
npm test           # 单元测试
npm run lint       # ESLint 和 Prettier
```

数据库在 `data/cms`（PGlite，不进仓库）；第一次启动时从官网的 `content/site.json` 和 messages 导入，做成第 1 版。

## 更新记录

### v2.0.0（2026-11-15）：拿取与锁定、工作流的每一步、版本记录、英文界面

- **文件和拿取**：每个页面、区块、全局资料和每条界面文字都是一个文件，有三种状态：未拿取、在某人名下（拿取）、在工作流里（锁定）。只有拿取了
  才能改；别人名下的可以“接手”（对方已保存的修改都留着）；签入后锁定，谁都不能拿取或修改，直到它离开工作流。新建的页面和区块自动在新建的人名下。
  中心页、区块列表、界面文字和每个编辑页都标出每个文件的状态；不在你名下时，编辑页的输入框是灰的。
- **我的文件**：新页面，列出在你名下的文件，可以几个一起签入、放回（修改留着，谁都能拿取）或丢弃（回到正式站的版本；从没发布过的新文件会删掉）；
  也列出你签入的、还在工作流里的文件。左边菜单显示在你名下和在工作流里的文件数。界面文字表格可以勾选多条一起拿取、签入或放回。
- **工作流**：新页面，取代原来的“签入”和“发布”。“已签入”一列：勾选文件推到预览站，或终止工作流（文件回到签入的人名下，修改留着）。
  “预览站”一列：勾选文件推到正式站（只推选的，预览站上别的文件留着：预览站的版本只在 CMS 预览和预览站），或退回签入（预览站重新构建，不再有它们，
  文件仍锁定）。构建失败时文件留在原来那一步。部署记录写明每次做了什么、几个文件。页面的新区块会跟着页面一起签入、一起推。
- **版本**：每个文件的“版本”列出每次签入（谁、什么时候、说明），标出正式站的版本、工作流里的版本、当前草稿，以及上过哪几版正式站；拿取后可以把
  任何一个版本恢复为草稿。紧急情况下，管理员和超级管理员可以让正式站整体回到以前上过正式站的一版（显示和现在有几处不同），之后预览站自动重建。
- **英文界面**：右上角切换中文和 English（这台浏览器记住）；所有页面、提示、检查出的问题和部署记录都有两种语言，区块类型和字段名也有英文。
  CMS 预览（cms-preview）顶上的条和 Edit 按钮跟着页面语言：简体和繁體页面是中文，English 和 Français 页面是英文。
- **上传**：上传要改的文件如果没人拿取，会自动拿取到你名下；别人名下的或在工作流里的会拒绝，什么都不改。
- **修正**：v1 的“发布”页从没进过仓库（.gitignore 的 deploy/ 把它也忽略了）；现在只忽略根目录的 deploy/ 和 data/。XML 解析库升级到
  5.12.1（修一个安全问题）。
- **数据**：数据库第 2 次迁移加了每个文件的状态、版本清单和部署内容；旧数据库会自动迁移。本机的数据库重新导入了官网内容（旧的存为
  data/cms-v1-2026-11-15），首页导语的繁體修正（擴充套件 → 擴展）按新流程签入、推到了预览站。
- **验证**：单元测试 27 项通过（拿取、接手、放回、丢弃、签入、终止、推到预览站、退回签入、推到正式站、页面带新区块、版本恢复、正式站回滚、
  一次只部署一个、上传的拿取、两种语言的消息、迁移）；中英文两种界面下每个页面都打开检查过；在浏览器里实际走了一遍拿取、修改、签入、推到预览站、
  退回签入、再推到预览站（真实构建）。没有推到正式站。

### v1.1.0（2026-11-15）：推到正式站只推内容，本机有没推送的代码也能发布

- **推到正式站**：现在在一个临时的工作目录里，以 GitHub 上官网的最新版本为底，只提交 content/site.json 并推送。开发者本机还没推送的代码提交不会被一起推上去，也不会挡住发布（以前会拒绝）。推送后本机的官网仓库落后 GitHub 一个提交，下次开发者推送前先拉取即可。
- **修正**：在 Windows 上，提交说明里的空格会让提交失败，推到正式站会什么都没推上去；已修好。
- **验证**：单元测试 15 项通过，其中一项用本机的空仓库当 GitHub，真的走一遍推到正式站：GitHub 上只多一个内容提交，本机的代码提交留在本机。

### v1.0.1（2026-11-15）：“用简体生成繁體”不再把“扩展”写成“擴充套件”

- **繁體转换**：OpenCC 的台湾词表把“扩展”当成软件的“扩展程序”，转成“擴充套件”；现在改为“擴展”。首页导语里的这一处已经在 CMS 里改好并签入，推到了预览站（第 2 版），正式站等推送。
- **验证**：单元测试 14 项通过。

### v1.0.0（2026-11-15）：网站内容管理上线

- **CMS 中心页**：所有页面按地址排成目录树，启用、停用和待删除的都看得到，每页标出未签入的修改；区块按类型列出（横幅、折叠问答、自由 HTML 等），
  标出没用在页面上的；预览站和正式站各是第几版。
- **编辑**：页面（地址、启用、宽度、留白、标题和描述，区块的顺序、增删）、区块（按类型的表单）、全局资料（公司、页头、页脚、作品、网站标题）和
  界面文字（约 400 条），都是四种语言并排；“用简体生成繁體”按台湾用法转换，再按 App 的用词改几处。每次保存都先检查，错在哪一项、为什么都写清楚。
- **CMS 预览**：带 Edit 的官网，每个区块、页头和页脚上都有 Edit，点了直接去编辑；顶上一条可以切换“已签入”和“草稿”，改了几秒内就更新。
- **流程**：保存（草稿）→ 签入（勾选、写说明；页面里新加的区块一起签入）→ 推到预览站（做成一个版本并构建）→ 推到正式站（提交 content/site.json 并推送）；
  部署记录、每一版和预览站、正式站之间的改动都看得到，旧版本可以再部署。推到正式站只有管理员和超级管理员能做；官网仓库里有没推送的代码时会拒绝。
- **下载与上传**：JSON 和 XML 两种格式，整个网站、界面文字、页面、区块、全局资料都可以；上传先检查、列出改动再写入，新地址的页面会新建（先停用）。
- **登录**：用公司的员工账号，从官网“我的账号”进入，不用另设密码；角色来自禄命秘解管理后台的“人员与权限”。
- **验证**：单元测试 13 项通过（导入、检查、草稿与签入、发布、JSON 和 XML 往返、上传新建页面、登录角色、繁體转换）。
