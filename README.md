# Cameyware 网站内容管理（CMS）

公司官网（www.cameyware.com，仓库 `C:\Cameyware`）的内容管理系统：页面、区块、全局资料和界面文字都存在这里自己的数据库里，
用四种语言（简体、繁體、English、Français）编辑，签入后推到预览站，检查过再推到正式站，不用再改代码、推代码。

## 网址

| 网址                                                           | 本机                  | 是什么                                               |
| -------------------------------------------------------------- | --------------------- | ---------------------------------------------------- |
| [cms-edit.cameyware.com](https://cms-edit.cameyware.com)       | http://127.0.0.1:8790 | CMS 中心页和各个编辑页                               |
| [cms-preview.cameyware.com](https://cms-preview.cameyware.com) | http://127.0.0.1:8791 | 带 Edit 的官网：每个区块上都有 Edit，点了去改它      |
| preview.cameyware.com                                          | http://127.0.0.1:8787 | 预览站（禄命秘解的服务器），“推到预览站”后是新的一版 |
| www.cameyware.com                                              | —                     | 正式站（Cloudflare Pages），“推到正式站”后几分钟上线 |

两个 CMS 网址要在 Cloudflare 隧道里各加一条公共主机名，并放进保护预览站的 Access 应用（见 docs/tech-plan.md）。

## 怎么用

1. **登录**：在官网登录员工账号，打开“我的账号” → “网站内容管理” → “进入 CMS”。网站编辑、管理员和超级管理员能进；只有管理员和
   超级管理员能推到正式站。
2. **改内容**：在 cms-preview 上点区块的 Edit，或在中心页打开页面、区块、全局资料、界面文字。保存的是草稿：CMS 预览切到“草稿”就能看到。
3. **签入**：在“签入”页勾选要签入的修改，写一句说明。签入后 CMS 预览（“已签入”）马上是新的。
4. **推到预览站**：在“发布”页点“推到预览站”：签入的内容做成一个版本，构建好换到 preview.cameyware.com（一两分钟）。
5. **推到正式站**：检查过预览站后点“推到正式站”：这一版提交到官网仓库并推送，Cloudflare 几分钟后上线。任何一个旧版本都可以再部署一次（回滚）。
6. **下载与上传**：整个网站、界面文字、单个页面、区块或全局资料都能下载成 JSON 或 XML，改好再上传；先列出会改什么，确认后写成草稿。上传一个地址还没有的页面，就新建一个页面。

## 区块类型

横幅、作品横幅、页面标题、账号卡片、精选作品、作品列表、卡片网格、服务卡片、折叠问答、提示条、公司联系方式、图文、自由 HTML、图片、
按钮组。每种类型在官网里有自己的显示方式（`C:\Cameyware\src\cms\views.tsx`），字段写在官网的 `cms/types.json`。自由 HTML 可以放脚本，
在隔离框里运行，碰不到网站的登录信息。

## 命令

```
npm start          # 启动 CMS（8790）和 CMS 预览（8791）；第一次会构建 CMS 和 CMS 预览站
npm run build:site # CMS 没运行时重建 CMS 预览站（运行时用中心页的“重建 CMS 预览站”）
npm run sync       # 从官网和禄命秘解同步内容模型、区块目录和网址
npm test           # 单元测试
npm run lint       # ESLint 和 Prettier
```

数据库在 `data/cms`（PGlite，不进仓库）；第一次启动时从官网的 `content/site.json` 和 messages 导入，做成第 1 版。

## 更新记录

### v1.0.1（2026-11-15）：“用简体生成繁體”不再把“扩展”写成“擴充套件”

- **繁體转换**：OpenCC 的台湾词表把“扩展”当成软件的“扩展程序”，转成“擴充套件”；现在改为“擴展”。首页导语里的这一处已经在 CMS 里改好并签入，推到了预览站（第 2 版），正式站等推送。
- **验证**：单元测试 14 项通过。

### v1.0.0（2026-11-15）：网站内容管理上线

- **CMS 中心页**：所有页面按地址排成目录树，启用、停用和待删除的都看得到，每页标出未签入的修改；区块按类型列出（横幅、折叠问答、自由 HTML 等），
  标出没用在页面上的；预览站和正式站各是第几版。
- **编辑**：页面（地址、启用、宽度、留白、标题和描述，区块的顺序、增删）、区块（按类型的表单）、全局资料（公司、页头、页脚、作品、网站标题）和
  界面文字（约 400 条），都是四种语言并排；“用简体生成繁體”按台湾用法转换，再按 App 的用词改几处。每次保存都先检查，错在哪一项、为什么都写清楚。
- **CMS 预览**：带 Edit 的官网，每个区块、页头和页脚上都有 Edit，点了直接去编辑；顶上一条可以切换“已签入”和“草稿”，改了几秒内就更新。
- **流程**：保存（草稿）→ 签入（勾选、写说明；页面里新加的区块一起签入）→ 推到预览站（做成一个版本并构建）→ 推到正式站（提交 content/site.json 并推送）；
  部署记录、每一版和预览站、正式站之间的改动都看得到，旧版本可以再部署。推到正式站只有管理员和超级管理员能做；官网仓库里有没推送的代码时会拒绝。
- **下载与上传**：JSON 和 XML 两种格式，整个网站、界面文字、页面、区块、全局资料都可以；上传先检查、列出改动再写入，新地址的页面会新建（先停用）。
- **登录**：用公司的员工账号，从官网“我的账号”进入，不用另设密码；角色来自禄命秘解管理后台的“人员与权限”。
- **验证**：单元测试 13 项通过（导入、检查、草稿与签入、发布、JSON 和 XML 往返、上传新建页面、登录角色、繁體转换）。
