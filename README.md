# Cameyware 网站内容管理（CMS）

公司官网（www.cameyware.com，仓库 `C:\Cameyware`）的内容管理系统：页面、区块、全局资料和界面文字都存在这里自己的数据库里，
用四种语言（简体、繁體、English、Français）编辑，签入后推到预览站，检查过再推到正式站，不用再改代码、推代码。

## 网址

| 网址                                                           | 本机                  | 是什么                                               |
| -------------------------------------------------------------- | --------------------- | ---------------------------------------------------- |
| [cms-edit.cameyware.com](https://cms-edit.cameyware.com)       | http://127.0.0.1:8790 | CMS 中心页和各个编辑页                               |
| [cms-preview.cameyware.com](https://cms-preview.cameyware.com) | http://127.0.0.1:8791 | 带 Edit 的官网：每个区块上都有 Edit，点了去改它      |
| preview.cameyware.com                                          | http://127.0.0.1:8787 | 预览站（禄命秘解的服务器），“推到预览站”后是新的一版 |
| www.cameyware.com                                              | —                     | 正式站（Cloudflare Pages），“推到正式站”后几分钟上线 |

两个 CMS 网址要在 Cloudflare 隧道里各加一条公共主机名，并放进保护预览站的 Access 应用（见 docs/tech-plan.md）。

## 怎么用

1. **登录**：在官网登录员工账号，打开“我的账号” → “网站内容管理” → “进入 CMS”。网站编辑、管理员和超级管理员能进；只有管理员和
   超级管理员能推到正式站。右上角可以切换中文和 English。
2. **拿取**：每个页面、区块、模板、布局、全局资料和每个资源包都是一个文件。在内容树里勾选文件点“拿取”，或在它的编辑页上点“拿取”，它就在你名下，
   只有你能改；别人名下的可以“接手”；已签入工作流的锁定着，谁都拿不了。内容树的“总览”显示谁在做什么。
3. **改内容**：在 cms-preview 上点区块的 Edit，或在内容树里打开页面、区块、模板、布局、全局资料、资源包。保存的是草稿：CMS 预览切到“草稿”
   就能看到。页面由一行行组成，一行里可以并排放几个组件（同一个组件也可以放两次）：在页面编辑页把左边“可用组件”拖到一行里就和那一行的组件并排，
   拖到两行之间就自己成为新的一行（用共用的、新建或复制已有的区块）；把“新的一行”拖到两行之间先加一个空行。拖动行的标题栏给整行排序，拖动组件
   换到别的行，也可以用箭头；每个组件选它的样式（内置模板或“视图/组件样式”里在 CMS 写的）。页面的“元数据”里选布局（标准、首页、落地页、文章，
   或“视图/页面布局”里在 CMS 写的），每个布局都带官网的页头和页脚。
4. **加入工作流（任务）**：工作流以“任务”为单位，一个任务是一组一起走的文件，可以同时有很多个。在“我的文件”勾选拿取的文件（或在文件的编辑页、内容树里）
   点“加入工作流”：“我的任务”（默认，加到你进行中的任务）、“新建任务”（工单号可以不填，任务名必填）、“加到其他人的任务”（文件仍在你名下）。加入后
   文件锁定，CMS 预览马上能看到。不改了可以“放回”（修改留着，谁都能拿取）或“丢弃”（回到正式站的版本）。
5. **推进任务**：在“工作流”页选一个任务（我的任务 / 全部任务，按状态筛选、按工单号或任务名查找），上面是它的步骤和这一步能做的事：
   进行中 → 推到预览站 → 提交审批 → 管理员批准（或写明原因退回）→ 发布：现在发布，或定时发布（到时间 CMS 自动发布，可以取消定时）→ 已完成。
   预览站以后的步骤都可以“退回进行中”；进行中可以“终止任务”（文件回到加入它们的人名下，修改留着）。任务的文件按内容 / 视图分组，可以勾选
   “从任务移除”（在预览站时预览站跟着更新）、“拆成新任务”，也可以“导出任务”（JSON）。每个任务有自己的记录和部署。
   **推到预览站、退回进行中、从预览站移除不用等构建**：预览站是实时的，只改了内容时几秒就好；只有代码变了（官网的代码或内置模板）、或有新页面时
   才构建一次（一两分钟）。部署进行中，任务页上盖一层窗口，显示进度，完成前不能改这个任务，好了自己关上并提示结果。
6. **小铃铛**：右上角的铃铛显示有几条通知：管理员和超级管理员看到等待审批的任务，每个人看到别人对自己任务（自己建的或自己审批的）做的事
   （批准、退回和原因、发布、定时发布、失败）。打开就算看过；每分钟自动更新。
7. **版本**：每个文件的编辑页都有“版本”，列出每次签入，标出正式站的版本；拿取后可以把任何一个版本恢复为草稿，再照常签入。紧急情况下，
   管理员可以在“部署记录”的“所有版本”里让正式站整体回到以前上过正式站的一版。
8. **下载与上传**：整个网站、界面文字、单个页面（在页面列表里勾选，文件名是页面名，同名上传覆盖它）、区块、模板、布局或全局资料都能下载成 JSON
   或 XML，改好再上传；先列出会改什么，确认后写成草稿。
   页面下载成 WebPage（像 Bell 的 XML）：元数据、布局的路径、每个组件的区、顺序、内容文件和样式文件的路径。要改的文件要在你名下或没人拿取
   （会自动拿取）。上传一个地址还没有的页面，就新建一个页面。

## 区块类型

横幅、作品横幅、页面标题、账号卡片、精选作品、作品列表、卡片网格、服务卡片、折叠问答、提示条、公司联系方式、图文、自由 HTML、图片、
按钮组。每种类型在官网里有自己的显示方式（内置模板：`C:\Cameyware\src\cms\views\<类型>.tsx`，超级管理员可以在 CMS 里替换），字段写在官网的 `cms/types.json`。自由 HTML 可以放脚本，
在隔离框里运行，碰不到网站的登录信息。

## 命令

```
npm start          # 启动 CMS（8790）和 CMS 预览（8791）；第一次会构建 CMS 和 CMS 预览站
npm run build:site # CMS 没运行时重建 CMS 预览站（运行时用中心页的“重建 CMS 预览站”）
npm run sync       # 从官网和禄命秘解同步内容模型、区块目录和网址
npm test           # 单元测试
npm run lint       # ESLint 和 Prettier
```

数据库在 `data/cms`（PGlite，不进仓库）；第一次启动时从官网的 `content/site.json` 和 messages 导入，做成第 1 版。

## 更新记录

### v9.1.0（2026-11-16）：页面名和文件名都不带中文

- 页面、区块、组件样式（模板）和页面布局的名字只用英文字母、数字、_ 和 -，不带中文和空格；只有内容（文字、标题等）可以是中文。
- 页面名按英文标题生成；没有英文标题时按网址（比如 /events/ → events）。原来带中文的页面名已改成英文（禄命秘解_Lu_Ming_Mi_Jie → Lu_Ming_Mi_Jie）。
- 原来的区块按“所在页面的网址 + 类型”改了名，比如 contact_page_title、home_hero_banner、works_lumingmijie_support_accordion；组件样式按
  类型（hero_banner_style）；它们的历史版本一起改名，所以不会因为改名显示“已修改”，正式站内容不变。
- 新建或修改区块、样式、布局时，名字带中文或空格会被拒绝并说明规则；每个名字输入框下面都写着规则。复制页面时区块名加 _copy。
- 上传以前下载的文件（里面的名字还是中文）也可以：已有的文件保留现在的英文名，新文件按类型起英文名。

验证：lint、类型检查、70 个测试（新增 5 个：名字规则、初始内容的名字、拒绝中文名、旧文件改名连同版本、上传旧文件）；先在 CMS 的副本上用浏览器
检查了改名结果，再升级正式用的 CMS。

### v9.0.0（2026-11-16）：页面名、复制页面、按页面下载和上传、部署记录分页、版本里的预览站记录

**页面名**：每个页面有了自己的名字，按标题自动生成（有英文标题用英文，没有就用中文；空格和其他符号换成 _），比如 Contact、Help_support。
名字生成后就固定不变。内容树的页面列表上面显示页面名，下面是网址；页面编辑页的标题也是页面名。

**复制页面**：内容树 → 页面 → 新建页面，“从哪里开始”可以选空白页面，或者复制一个已有页面：布局、设置都一样，页面上的区块会复制成新的区块文件
（在你名下），两个页面以后各改各的。新页面先是停用的。

**按页面下载和上传**：页面列表里勾选一个页面，点“下载”选 JSON 或 XML，文件名就是页面名（比如 Contact.json）。改好后点“上传”：和文件同名的
页面会被文件内容覆盖（写成草稿）；先列出会改什么，确认后才写入；页面和它的区块没人拿取时自动拿取到你名下，别人名下的或在工作流里的会拒绝。
文件名对不上任何页面、或者和勾选的页面不一样，会拒绝并说明。

**下载与上传**：页面上先说明这一页能做什么：下载整个网站、下载界面文字、单个文件去哪里下载、上传会怎样、上传不会直接改网站。

**部署记录**：底部有“每页”（20 / 50 / 100）和翻页，只有一页时也显示。

**版本**：每个文件的版本里，推到过预览站的版本会写明“上过预览站：第 N 版”，和“上过正式站”一样；拿取后可以把它恢复成草稿。每次加入工作流都会
留下一个版本，推到预览站的内容不会丢。

验证：lint、类型检查、65 个测试（新增 5 个：页面名、复制页面、按名字上传、拒绝、版本的预览站记录）；在 CMS 的一个副本上用浏览器走了 13 项
（页面名、复制、下载再上传、拒绝、每页、说明、版本）。

### v8.0.1（2026-11-16）：丢弃新建又删除的文件后不再出现 404

- 修好：新建的模板（或区块、页面、布局）删除后再“丢弃”，以前会停在一个 404 页面。现在从没发布过的文件丢弃后回到它所在的文件夹（内容树里）。
- 打开一个已经不在的文件（比如另一个标签页还开着它）时，不再是空白的 404，而是 CMS 自己的页面：说明它可能已丢弃或删除，有“回到内容树”和“我的文件”。

验证：lint、类型检查、60 个测试；在 CMS 的一个副本上用浏览器新建模板、删除、丢弃，再打开它原来的地址。

### v8.0.0（2026-11-16）：推到预览站不用等构建，部署时的遮罩窗口

**预览站实时更新**（需要官网 v2.5.0）：

- 预览站（preview.cameyware.com）现在是“实时”的构建：页面的内容从和它放在一起的 `cms-content.json` 读取。推到预览站、退回进行中、从预览站
  移除文件时，CMS 只换这个文件：几秒就好，不用构建，开着的预览站页面半分钟内自己更新。
- 只有这几种情况才构建一次（一两分钟）：官网的代码变了（官网仓库的 main）、内置模板（代码）有改动、有预览站上还没有的新页面，或者预览站还不是
  实时的版本（升级后的第一次推送）。部署记录的日志里写明这次是“只换了内容”还是“构建一次预览站”。
- 禄命秘解的 npm run all 也用同样的方式构建预览站，并写好内容文件。

**部署时的遮罩窗口**：任务正在部署（推到预览站、退回、从预览站移除、发布）时，任务页上盖一层窗口：写明在做什么，显示部署的输出，有日志的
链接；完成前不能关，也点不到页面上的任何按钮。部署结束窗口自己关上，并提示“部署完成”或“部署失败”（失败时任务留在原来那一步）。

验证：lint、类型检查、60 个测试（新增 1 个：什么时候只换内容、什么时候要构建）；在 CMS 的一个副本上（自己的数据库、自己的官网副本）用浏览器走了
一遍：第一次推送在遮罩窗口下构建一次，之后推送和退回都在几秒内完成、没有构建，预览站页面跟着内容文件变。

### v7.0.0（2026-11-16）：工作流任务（像 Bell 的 Workflow Job Manager），审批、定时发布、小铃铛

**工作流以任务为单位**：

- 一个任务 = 工单号（可以不填）+ 任务名 + 自己的文件 + 自己的步骤。可以同时有很多个任务，几个任务可以用同一个工单号（比如 batch 1、2、3），
  各走各的；一个文件同一时间只在一个任务里。
- **加入工作流**（“我的文件”、文件编辑页、内容树）弹出的窗口先列出选中的内容，下面三个页签：**我的任务**（默认，选一个你进行中的任务）、
  **新建任务**（工单号、任务名）、**加到其他人的任务**（别人进行中的任务；文件仍在你名下，离开任务时回到你这里）。你还没有进行中的任务时
  直接打开“新建任务”。页面上还没发布过的新区块、新样式和新布局（在你名下的）会一起加入。
- **我的文件**：上面是可以加入工作流的文件，下面是“我的任务”（未结束的），点任务名在新标签页打开它。

**工作流页（任务管理）**：

- 上面是选中的任务：#编号、工单号、任务名、状态、创建人、审批人，和步骤条：进行中 → 预览站 → 待审批 → 已批准（已定时）→ 已完成。
  按钮只出现在这一步能用的地方：
  - 进行中：推到预览站、终止任务（文件回到加入它们的人名下，修改留着）。
  - 预览站：提交审批（可以给审批人写一句）、退回进行中。
  - 待审批：管理员和超级管理员可以批准（可写说明）或退回（要写原因，任务回到预览站）。
  - 已批准：发布到正式站，选“现在发布”或“定时发布”（选日期和时间，至少一分钟以后；到时间 CMS 每分钟检查一次自动发布）。
  - 已定时：取消定时（回到已批准）、退回。
  - 预览站以后的步骤都可以退回进行中（预览站更新，不再有它的文件，审批要重来）。
- 任务的创建人、管理员和超级管理员能推进任务；批准、退回和发布只有管理员和超级管理员能做。网站编辑提交，管理员批准后发布。
- 中间是任务列表：我的任务 / 全部任务，按状态筛选（默认未结束），按工单号、任务名或编号查找，每页 20 个，点一行选中它。
- 下面是任务的文件，按“内容”和“视图”分组：勾选后可以 **从任务移除**（进行中马上移除；在预览站时预览站更新好以后移除）、
  **拆成新任务**（窗口里列出任务的全部文件，要移走的加粗；新任务在同一步，工单号默认一样）；**导出任务** 下载 JSON（任务、文件、记录）。
- 每个任务有自己的记录（谁在什么时候做了什么，退回的原因）和自己的部署（链接到部署记录）。当前部署和三个站点还在页面上。
- 推进一个页面时，它还没发布过的新区块如果在别的任务里，会跟着这个任务走（那个任务的记录里写明）。

**小铃铛**（右上角，不发邮件）：红色数字是通知的条数：等你审批的任务（管理员和超级管理员）加上你的任务的新动态（别人批准、退回和原因、发布、
定时发布、失败）。点开列出来，顶上写“N 条新通知”，点一条打开那个任务；打开就算看过。每分钟自动更新。

**原来的工作流**：升级时每次签入、每一步变成一个任务（名字是原来的签入说明），比如 #1 webfl5019、#2 webfl1234 都在预览站。

验证：lint、类型检查、59 个测试（新增 9 个：任务的新建、加入、移除、拆分、终止、审批、退回、定时、失败、带走别的任务的新区块、
加到别人的任务、在预览站移除、旧工作流的转换）；在 CMS 的一个副本上（自己的数据库、自己的官网副本推到一个本地的仓库，不碰正在用的 CMS
和 GitHub）用浏览器从头走了一遍。

### v6.1.0（2026-11-16）：区块用在哪些页面，顶部的保存和预览，CMS 的网站图标

**用在哪些页面**（区块是可以几个页面共用的内容文件）：

- 区块的编辑页标题下有 **“用在 N 个页面”**，点开是一个列表：每个页面的地址（在新标签页打开它的编辑）、标题、停用的标出来，
  这个区块在那一页的每个位置（区和样式；同一页放了两次就两行），和“预览草稿”（新标签页）。页面多时（8 个起）可以按地址或标题查找。
  原来页面底部的“用在这些页面上”卡片去掉了。
- 页面编辑里，**共用的区块**（在两个以上的页面上）卡片上多一个 **“共用 · N 个页面”**，点开同样的列表，当前这一页标着“此页”。
- 组件属性里“用共用的”的表格多一列 **“用在”**：每个区块用在几个页面，点开看是哪些；点它不会选中那一行。
- 修好：在组件属性上面打开的“浏览”（样式）或“用在”列表，按 Esc 只关它自己，不再把组件属性一起关掉。

**顶部的保存和预览**（区块和全局内容的编辑页）：

- 标题右边有 **保存** 和 **预览**（底部的保存还在）。文件不在你名下时保存是灰的。
- **预览**在新标签页打开它的草稿：区块是打开它的那一页（或它用在的第一页），停在区块的位置；全局内容是你从预览站点“编辑”过来
  的那一页，或首页。有还没保存的修改时，预览先保存（存为草稿，签入前谁都看不到），再打开。区块还没用在页面上时预览是灰的，提示
  没有页面可预览。
